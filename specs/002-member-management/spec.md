# Feature Specification: User, Staff, PT & Member Management

**Feature Branch**: `002-member-management`
**Created**: 2026-05-30
**Status**: Approved
**Spec style**: SDD + Spec Kit — 9 components, EARS notation
**Source**: 03_SRS (UC-03, UC-03A, UC-04, UC-05), 04_REQUIREMENTS (FR-MEM)

> EARS legend như spec 001.

---

## 1. Context & Goal
Quản lý vòng đời hồ sơ người dùng: Admin quản lý tài khoản & Staff & PT; Admin/Staff quản lý hồ sơ hội viên. Là dữ liệu gốc cho membership, check-in, training. Mục tiêu: CRUD + tìm kiếm nhanh, dữ liệu không trùng, soft-delete bảo toàn lịch sử.

## 2. Actors
| Actor | Vai trò |
|---|---|
| Admin | CRUD tài khoản mọi role (Staff/PT/Member); quản lý hồ sơ PT |
| Staff | CRUD + tìm kiếm hồ sơ Member |
| PT | Xem hồ sơ Member được phân công (read-only) |
| Member | Xem/cập nhật hồ sơ cá nhân hạn chế |

## 3. Functional Requirements (EARS)
- **FR-USR-01 (Event):** WHEN Admin tạo tài khoản với email chưa tồn tại, THE system SHALL tạo User với role chỉ định và trạng thái Active. WHERE Admin không nhập `password`, THE system SHALL tự sinh mật khẩu tạm và trả về `initialPassword` (kèm `passwordAutoGenerated=true`) để Admin đưa cho người dùng; WHERE Admin nhập `password` (≥6 ký tự), THE system SHALL dùng mật khẩu đó.
- **FR-USR-02 (Unwanted):** IF email/phone đã tồn tại (chưa soft-delete), THEN THE system SHALL từ chối với 409.
- **FR-USR-03 (Ubiquitous):** THE system SHALL chỉ cho Admin tạo/sửa tài khoản role Staff và PT.
- **FR-MEM-01 (Event):** WHEN Admin/Staff tạo hồ sơ Member hợp lệ, THE system SHALL lưu MemberProfile liên kết User role Member. WHERE email chưa tồn tại, THE system SHALL tạo mới cả User (role Member) + MemberProfile. WHERE email đã thuộc một tài khoản Member chưa có hồ sơ (vd member tự đăng ký ở spec 001), THE system SHALL chỉ tạo MemberProfile gắn vào tài khoản đó và KHÔNG thay đổi mật khẩu (bảo mật); WHERE tài khoản đó đã có hồ sơ hoặc email thuộc role khác, THE system SHALL trả 409.
- **FR-MEM-02 (Event):** WHEN Admin/Staff tìm kiếm theo tên/email/SĐT, THE system SHALL trả danh sách phân trang khớp (không phân biệt hoa thường).
- **FR-MEM-03 (Event):** WHEN Admin/Staff cập nhật hồ sơ Member, THE system SHALL validate và lưu, cập nhật UpdatedAt.
- **FR-MEM-04 (Ubiquitous):** THE system SHALL xóa hồ sơ theo cơ chế soft-delete (IsDeleted=1), KHÔNG xóa cứng (DATA-01).
- **FR-MEM-05 (Optional):** WHERE người gọi là Member, THE system SHALL chỉ cho xem/cập nhật hồ sơ của chính mình (ownership check).
- **FR-PT-PROF-01 (Event):** WHEN Admin tạo hồ sơ PT, THE system SHALL lưu TrainerProfile liên kết User role PT.

## 4. Non-functional Requirements
- **NFR-01:** Tìm kiếm < 1s với ~1000 hội viên; có phân trang (mặc định 20/trang).
- **NFR-02:** Mọi mutating action ghi AuditLog (AUDIT-01).
- **NFR-03:** Dữ liệu PII (SĐT, email) không xuất hiện trong log.

## 5. Data Model
- **MemberProfiles**(Id, UserId→Users[1-1], DateOfBirth, Gender, Address, EmergencyContact, JoinedAt, IsDeleted, CreatedAt, UpdatedAt)
- **TrainerProfiles**(Id, UserId→Users[1-1], Specialty, Bio, Gender, DateOfBirth, YearsOfExperience, IsDeleted, CreatedAt, UpdatedAt)
- Dùng chung **Users/Roles** (spec 001). Xem `05_DATABASE_SPEC.md`, `15_DATABASE_SCHEMA.md`.

## 6. API Spec
| Method | Path | Role | Request | Success | Lỗi |
|---|---|---|---|---|---|
| POST | /api/v1/users | Admin | {fullName, email, phone?, role, password?} | 201 (kèm initialPassword) | 400, 409 |
| GET | /api/members?query=&page= | Admin, Staff | — | 200 (paged) | 401, 403 |
| POST | /api/members | Admin, Staff | {fullName, email, phone, dob,...} | 201 | 400, 409 |

## 7. Error Handling (EARS Unwanted)
- IF dữ liệu không hợp lệ (email sai định dạng, thiếu field bắt buộc), THEN 400 `VALIDATION_ERROR`.
- IF email/phone trùng, THEN 409 `DUPLICATE`.
- IF id không tồn tại/đã soft-delete, THEN 404 `NOT_FOUND`.
- IF Member truy cập hồ sơ người khác, THEN 403 `FORBIDDEN`.
- IF PT xem Member không được phân công, THEN 403 `FORBIDDEN`.

## 8. Acceptance Criteria (Given-When-Then)
- [ ] **AC-01:** Given email mới, When Admin tạo Staff, Then tài khoản Staff Active được tạo.
- [ ] **AC-02:** Given email đã dùng, When tạo, Then 409.
- [ ] **AC-03:** Given 1000 member, When Staff tìm theo SĐT một phần, Then trả kết quả phân trang đúng < 1s.
- [ ] **AC-04:** Given Member đăng nhập, When xem hồ sơ người khác, Then 403.
- [ ] **AC-05:** Given Admin xóa Member, When truy vấn lại, Then không hiện trong danh sách nhưng vẫn còn trong DB (IsDeleted=1).
- [ ] **AC-06:** Given Staff tạo Member, When hoàn tất, Then có bản ghi AuditLog `CREATE_MEMBER`.

## 9. Out of Scope
- Import hàng loạt từ Excel/CSV, ảnh đại diện (secondary), xác minh danh tính KYC, đăng ký công khai.
